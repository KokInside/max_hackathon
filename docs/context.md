### Про HTTPS-сертификат

Сертификат Минцифры не нужен:
- ТЗ требует для мини-приложения только HTTPS (стр. 15);
- для вебхука справочные факты требуют «сертификат доверенного центра»;
- Let's Encrypt — общепризнанный доверенный центр, бесплатный. Caddy получает и продлевает его сам, достаточно домена с A-записью на VPS.

**ASSUMPTION:** MAX принимает сертификаты Let's Encrypt для вебхука и мини-приложения. Проверяем первым делом (T03, T05). План Б — в §5.

Сертификат Минцифры нужен в обратную сторону: наш сервер обращается к `platform-api2.max.ru`, а его сертификат выдан российским УЦ (см. §3). Корневой сертификат Минцифры добавляем в доверенные внутри контейнера — только для исходящих запросов.

## 4. Платформа MAX: ограничения → проектные решения

### 4.1. Факты (из справочных фактов постановки, не перепроверялись)

- Bot API: `platform-api2.max.ru`, токен в заголовке `Authorization`, лимит 30 запросов/с.
- Прод — только вебхук по HTTPS с сертификатом доверенного центра; long polling — только для локальной разработки.
- Кнопки: callback, link, request_contact, request_geo_location, open_app, message, clipboard. При пересылке сообщения в другой чат кнопки теряются.
- Метода добавления участников в групповой чат нет.
- Есть официальные библиотеки для JS и Go и библиотека компонентов MAX UI.
- MAX Bridge: initData (пользователь, чат и его тип, `start_param` из `?startapp=`), серверная валидация initData обязательна; requestContact, downloadFile, shareMaxContent, openCodeReader, BackButton, enableClosingConfirmation.
- В вебе не поддерживаются DeviceStorage, SecureStorage, shareContent; HapticFeedback и биометрия не поддерживаются десктопом и вебом.

## 5. Риски среды

| Риск | Вероятность / влияние | План Б |
|---|---|---|
| Нет домена: делегирование `.ru` занимает часы | Средняя / блокирует регистрацию мини-приложения | Сразу использовать бесплатное имя вида `<IP>.sslip.io` (Let's Encrypt выдаёт на него сертификат), позже переключиться на свой домен |
| MAX не принимает Let's Encrypt для вебхука (ASSUMPTION не подтвердилась) | Низкая / высокое | Бот на VPS временно работает через long polling (известное ограничение, указано в README); мини-приложению достаточно HTTPS |
| Нет корневого сертификата Минцифры в контейнере | Высокая, если забыть / бот молчит | Сертификат в репозитории (`certs/russian_trusted_root_ca.crt` с указанием источника) + `update-ca-certificates` в Dockerfile; проверка `GET /me` к Bot API при старте |
| Нестабильность Bot API (5xx, 429, тайм-ауты) | Средняя / сообщения теряются | Очередь исходящих ≤ 25 rps, повтор с экспоненциальной задержкой, идемпотентные напоминания (`sent_at`), логирование |
| Документация MAX изменилась (REQ-48) | Средняя / сломается интеграция | Весь MAX-код изолирован в модуле `max/`; сверка D1 и D5 |
| Проверяющий запускает compose с прод-токеном | Средняя / перехват обновлений прод-бота | По умолчанию `BOT_MODE=off` в `.env.example`; вопрос О-2 организаторам; предупреждение в README |
| VPS недоступен в период проверки | Низкая / 0 баллов (REQ-82) | `restart: unless-stopped`, healthcheck, ежедневный `pg_dump`, внешний бесплатный пинг-мониторинг; инструкция восстановления за 15 минут |
| Модерация мини-приложения в MAX | Неизвестно | Регистрируем в первый вечер (T03), чтобы запас был максимальным |
